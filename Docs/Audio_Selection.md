# 标准音频选型与现有文件

<!-- doc-status: current-candidate-assets; reviewed: 2026-10-25 -->

## 结论和当前边界

2026-10-25用户确认：**老师允许标准音频自行选择**。任务书PDF中“实验室提供”的文字保留为原文历史依据，本次选型按老师最新说明执行。

建议以 **2–6kHz、50ms线性上扫频（chirp），48kHz、单声道PCM16 WAV** 作为首个标准音候选，后续采用模板相关与质量门限定位。它适合作为当前手机外放、板载麦克风链路的起点；尚未完成手机/音箱/教室的对照录音，不能称为普遍最优，也没有实测识别概率。

现有 `App/Detector/sound_detector.*` 是能量候选检测，默认64帧窗口、连续2窗确认，能定位候选窗并关联本地时间模型，**还不能辨认指定扫频音、排除语音/击掌或保证到达时刻精度**。本次仅准备文件，不接入新检测算法，不烧录、不播放。

## 为什么优先选短扫频

| 信号 | 对本项目的利点 | 主要限制 | 当前选择 |
| --- | --- | --- | --- |
| 短线性扫频 | 有明确频率轨迹；可积累整段匹配证据，便于时间定位及区别普通声音 | 反射、播放失真、采样时钟误差仍会改变相关峰 | 优先实测 |
| 单频“滴”声 | 易播放，能量触发简单 | 周期重复产生多个相似相关峰；仅频率相同不代表目标事件 | 用作对照，不作首选模板 |
| 语音、音乐 | 文件容易获得 | 有复杂包络与重复片段；不利于统一事件定义和抗误触发 | 不优先 |
| 击掌 | 不需要文件，瞬态明显 | 波形随人和动作变化；课程要求与标准音频分型 | 独立模式，后续处理 |
| 18–22kHz扫频 | 可减轻可听干扰 | 接近手机扬声器/麦克风高频边界，更换播放设备风险较高 | 暂不首选 |
| 伪随机序列/编码多音 | 可设计有区分度的匹配特征 | 需要额外设计、限带与设备验证；不能凭名称断言优于chirp | 后续有证据再比较 |

[BeepBeep原论文](https://www.cs.purdue.edu/homes/chunyi/pubs/sensys106-beepbeep.pdf)第4.2–4.3节采用2–6kHz线性chirp、50ms长度及相关检测，并讨论其所测旧款手机的高频衰减和多径问题。这支持本次候选参数的工程依据；其双向测距协议、设备与我们的PTP/TDOA不同，不移用其测距成绩。本文的渐变包络也不是论文实现的原样复刻。

判定成功率需要固定测试条件：实际播放次数、正确检测数、漏检数、重复输出数、60秒背景误触发数，以及不同音源的误分类数。只把正确次数除以播放次数仍不足以证明测距精度，必须另测时间误差/距离误差。

## 直接使用哪个文件

所有文件位于 [`Data/Audio/`](../Data/Audio/)。

| 文件 | 来源 | 格式与作用 |
| --- | --- | --- |
| [standard_chirp_2-6khz_10x_20s.wav](../Data/Audio/standard_chirp_2-6khz_10x_20s.wav) | 项目按公式合成 | **手机播放这个**：20秒10次，事件在1、3、…、19秒，间隔2秒；48kHz/PCM16/单声道 |
| [chirp_2-6khz_50ms_template.wav](../Data/Audio/chirp_2-6khz_50ms_template.wav) | 项目按公式合成 | **算法模板**：2400采样点，无前后静音，50ms；也可单次播放，但短文件可能受播放器启停影响 |
| [reference_log_sweep_20hz_21khz_15s.wav](../Data/Audio/reference_log_sweep_20hz_21khz_15s.wav) | 网上下载原件 | 全频段对数扫频，实读44.1kHz/PCM16/单声道，15.276462585秒；仅供扫频/频响对照，不选为标准事件 |

两个合成文件峰值约半幅（约−6dBFS），两端各48点、约1ms的半余弦渐变，减小硬切换瞬态。50ms内频率按连续公式从2000Hz上升至6000Hz，末点在50ms之前。模板坐标原点为采样点0；首点因渐变为0，不能用“首个非零点”或能量越阈点代替模板原点。

合成文件不包含论文中的扬声器预热前导，不是下载文件的片段或转换。后续若增加前导、编码或更改包络，必须同时更换模板与版本、重新校准，不得混用旧时间偏移。

## 本次验证能说明什么

`candidate_manifest.json` 记录合成配方、事件采样点、实际WAV格式、SHA256和理想自相关指标。`reference_source.json` 记录下载原件与许可；[署名说明](../Data/Audio/ATTRIBUTION.md)随文件保留。

生成脚本会核对两个WAV的全部PCM样本、10个事件位置和全部静音、无截幅、格式、清单及下载原件散列。自相关对照使用同样50ms长度/渐变包络的3kHz单音，指标为 `max(|R(lag)|)/R(0)`，限定正延迟至少24点（0.5ms）。这是理想数字波形的周期歧义指标，数值更小表示这个延迟区间中的竞争峰较弱；**不是有噪声检测率，也不代表主峰宽度、房间多径表现或板端精度**。相关运算的定义可参考 [SciPy官方文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.correlate.html)。

本次逐样本和清单核对通过，另用SciPy FFT相关独立找出10个事件：起点48000、144000、…、912000，间隔均96000采样点。上述自相关竞争峰指标为扫频约0.126、单频约0.995，支持扫频的周期歧义较小；不能解释成12.6%或99.5%的识别率。没有进行播放或实物测试。

复现环境：Python3 + NumPy；本次Python3.13.3、NumPy2.4.3，独立相关核验使用SciPy1.18.0。仅运行下面脚本不需要SciPy。从工程根目录执行：

```powershell
# 重新生成两个项目候选WAV和清单；不会覆盖网上下载的参考原件
python -B Analysis/prepare_standard_audio.py
# 只核对已有文件，不重写
python -B Analysis/prepare_standard_audio.py --check
```

无需固件构建、烧录或CubeMX变更；无新IRQ/DMA/缓存关系。

## 播放与后续验收

1. 将20秒循环版以文件方式复制到手机，保留原始WAV；不要经语音消息、有损转码或蓝牙再作为计时参考。关闭可关闭的均衡/空间音效，固定播放设备、位置与音量，并记录设置。
2. 从较低音量开始，确认板端峰值不过载后再固定音量；不要靠增大音量掩盖检测算法问题。手机外放即可，不需要接线向板上注入信号。
3. 接入指定模板匹配后，固定位置先测10次，核对10次事件、无重复/漏检，再测60秒静默、语音/击掌负样本和另一播放设备。当前能量候选日志可观察幅值，但不能用于宣称标准音识别通过。
4. 到达时刻应取模板在录音流中的位置，再走已建立的帧→本地PTP模型；不能用串口到达电脑的时刻、播放按钮时刻、DMA回调时刻或最大的反射峰代替直达声时间。
5. 播放文件名义48kHz；板端SAI时钟推导约47991.071Hz，实际仍随晶振变化。模板匹配要考虑收发采样率差，按接收采样率重采样/容差匹配，并用板端时间模型换算。单个50ms事件的名义速率差已约0.45采样点，不能把名义48kHz直接当真实时间。
6. 在普通教室做设备/距离对照后再冻结正式标准文件与SHA256；后续两板同步、声学固定延迟/多径和距离标定仍独立验收。本次文件验证不证明±100μs、±10mm或两板相差≤1mm。
