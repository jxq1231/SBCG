# M1.4 单板双向UDP断线恢复验收

日期：2026-10-20。运行基线为`671be76`（SBCG-M1.3-UDP应用）。独立目标是两次链路断开后，电脑请求/板端应答与原5005观测通道均自行恢复，断线期间串口心跳继续。**本次实物联合验收通过**，不是新增固件功能，也不将整个双板M1标记为完成。

## 执行方式与范围

用户要求自动执行后，助手检查192.168.10.100/24和UDP 5005/6006空闲，同时运行现有两个工具。电脑为Realtek有线网卡，板端为192.168.10.1，UID为001A002D/30365105/36363631。用户仍负责物理网线操作；助手在两次操作提示后，实际记录到两组PHY DOWN/UP，不依据提示推定断线时长。

实际执行命令（工程根目录）：

```powershell
python -B Tools/Monitor/udp_monitor.py --uid 001A002D:30365105:36363631 --duration 90 --log Logs/UDP/m14-auto-20261020-6b3588-heartbeat.jsonl
python -B Tools/Monitor/udp_probe.py --uid 001A002D:30365105:36363631 --count 60 --log Logs/UDP/m14-auto-20261020-6b3588-probe.jsonl
```

两工具并行运行。另使用系统System.IO.Ports读取COM3，115200、8N1、无流控，DTR/RTS为false，采集90秒到`Logs/UDP/m14-auto-20261020-6b3588-serial.txt`。采集结束关闭串口，两个UDP socket也已释放；没有抢占已有工具或关闭用户进程。人工串口观察仍使用[SerialWeb](../SerialWeb.md)。

没有烧录、调试复位、Flash读取/比较或选项字节操作，没有禁用/启用电脑网卡、改变IP、防火墙、CubeMX或固件源码。No CubeMX change required。

## 判定与边界

两个工具原summary均保持`status=REVIEW`、`hardware_verified=false`，退出码均为1。正常窗口的零超时/零缺口条件在主动断线时不满足，这不是工具崩溃，也不把摘要改成PASS。联合验收通过的依据是两次PHY恢复、两路UDP恢复、连续心跳，以及19个缺口与19个本地断线跳过逐项对应。

21.111%的5005缺口比例和19/60的请求未应答比例属于故障注入窗口，不能表述成正常链路随机丢包率；此前M1.3正常30发30收结果独立保留。没有精确物理插回时间，不能从无包间隔计算或承诺重连时延上限，也没有验证长时间压力、fatal DMA恢复、非法报文实物注入、第二板、PTP或测距精度。
