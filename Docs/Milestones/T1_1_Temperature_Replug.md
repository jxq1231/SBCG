更新：2026-10-22。**一次物理拔插的温度故障/恢复行为验证通过；采集存在电脑端中断空档，不能宣称整段连续网络零丢包或精确观察到15秒阈值跨越。**

## 实测结果

| 项目 | 观察结果 |
| --- | --- |
| 故障前最后有效值 | VERSION=135，27.1℃，40%RH，347723 mm/s |
| 断开后 | HOLD_LAST，随后观察到STALE；FRESH=0，旧温度/湿度/声速及版本均保持135 |
| 查询有效性 | AUTO/NONE/VALID=0，仅带VERSION=135，不输出可用温度或声速字段 |

| 持续恢复 | 新版本136～147共12个，恢复后继续观察约55.1秒；最终26.9℃、46%RH、347601 mm/s，整数声速逐条一致 |
| 预读/成功计数 | PRIME由2增至3，只有一次重预读；预读本身未发布新版本 |
| 故障计数 | TIMEOUT累计18，来自断开期间，首次恢复后不再增加；INIT/BUS/START/PULSE/CLOCK/CRC/RANGE/FORMAT均0 |
| 串口与板端服务 | 捕获窗口内心跳/PTP序号连续，TX_ERRORS及串口RX错误/溢出/续收错误均0；PTP保持LOCAL/SYNC=0 |
| UDP单向观察 | 第一段35包（SEQ656～690），恢复采集段90包（SEQ744～833），各段均无缺口、重复、乱序、非法或外来包；tick间隔均1000ms |
| 请求/时间交换 | 本轮旧30组RX/TX/ACK、新30组ACK/REPORT/四时刻完整，30组板端结果与真实C参考逐条完全一致；相关计数由此前30增至60，错误项保持0 |

`TIMEOUT=18`是累计故障计数，恢复后不清零；应结合STATE=OK、FRESH=1、新版本持续增加及TIMEOUT停止增长判断恢复，不能要求热插拔后累计计数重新变成0。

## 电脑端中断与证据边界

首段采集约35.27秒。脚本读取UTF-8中文操作确认时遗漏encoding参数，Windows默认GBK导致UnicodeDecodeError，采集关闭。这是电脑端脚本错误，首次失败记录和原始字节均保留，没有删除后重跑来掩盖。

用户仍保持传感器断开；脚本显式使用UTF-8后继续同一次物理拔插，第二段采集约90.16秒。未让用户重新拔插，也未重烧/复位。第二段首先观察STALE，之后通知用户插回，完整捕获PRIMING和后续新采样。

两段之间SEQ691～743共53个序号没有接收记录。它们属于**主机未观测区间，不作为网络丢包，也不作为已证明收到**；不能将35+90包称为一个连续125包零丢包窗口。15秒过期阈值的准确跨越也发生在此空档，最早实际捕获的STALE记录AGE_MS=66730。HOLD_LAST记录年龄均小于15000，STALE记录年龄均大于等于15000，但本次不能证明15秒边界附近每一秒的状态。

重新打开串口时，ST-LINK VCP保留了一条旧SEQ691的UDP残行和一段旧心跳前缀，后一段与新的首条ENV拼在同一原始行。分析只在第二段开头限定位置、长度、前次心跳序号+1及首条ENV的条件下重新定位，记录被排除的原始前缀；不改写原始二进制/JSONL。后续任何坏行、BOOT、计数回退或异常均拒绝。两份串口JSONL可逐字节重构对应二进制。

因此本次结论为 `PASS_REPLUG_WITH_HOST_CAPTURE_GAP`：故障值保持、失效标识、重新预读和持续自动恢复已实测；**全程连续UDP丢包率、精确过期边界及长时间可靠性仍不在本次证明范围内**。不把此记录反向套用到R1旧固件，也不声称双板同步或测距精度达标。
