## 1. 目标、来源和当前起点

任务书要求使用两块STM32F746，在声源位于两板基线延长线时，依据两个麦克风的声音到达时差，自动测量**两麦克风之间的距离**及声源在A侧还是B侧。最终采集、同步、计算、结果判定和LCD显示均在板上完成，计算机仅可播放声音、观察输出或设置参数。

依据：用户提供的《嵌入式系统课程设计-分布式声波测距系统-设计任务书（V1.0）(1).pdf》，共5页；SHA256为`b29562bbc0d75b2bee70413f86f9655b2c810d4cab5ec587e3fc6d1102f99ee2`。未将原PDF复制到仓库。

## 4. 验收边界与待澄清项

1. 任务书第4页：只能使用课程发放的板、模块和连接线；真值是**麦克风开孔间距**，验收前标记位置，卷尺拉紧并垂直读数。
2. 声源位于基线延长线、距近板约0.5～1 m，尽量共线，音量适中；绝对误差指标使用指定标准音频和同一播放设备评定。
3. 击掌距近板约0.5～1 m，两次间隔≥1.5秒；不得借助电脑辅助测量或结果判定。开发分析工具不属于最终运行依赖。
4. B2的原文不能直接理解为两次播放的绝对时间戳相差≤100 μs，因为其中包含播放间隔。需明确播放周期/参考触发与统计口径，再分离重复检测误差；不得用未经确认的解释声称通过。
5. 任务书第5页要求设计报告给出同步、检测抖动、温度、多径和声源差异的误差预算，并对照实测。该工作应贯穿开发，而非最后补写结论。

## 6. 提高功能的实施顺序

1. **质量评估（A4）**：M4先预留必要的强度、相关峰、饱和和可信度数据，再完成标注/拒绝规则；不能以平滑掩盖无效输入。
2. **自动温度（A1）**：在基础手动温补通过后接入课程DHT11，测量温度读数的实际误差与响应；一只传感器的数据经网络共享，保留手动模式与故障状态。
3. **单点标定（A2）**：先明确修正的是固定双通道延迟还是比例误差；用一次已知距离建立参数，再用其余距离验证，不能逐距离重标定来满足单点要求。
4. **击掌识别（A3）**：单独验证瞬态检测、事件配对和音频/击掌分类互斥，不通过切换两个互不协同的程序冒充同时支持。
5. **量程扩展（A5）**：在近距离精度稳定后扩展事件窗口和可靠检测，分0.20～5 m、5～10 m验证噪声、多径和标定残差；不只改量程常量。
6. **同步波形（A6）**：使用共同时间窗与刷新时刻，并校核采样时钟映射。避免两板各自独立触发并强行对齐波形，否则无法证明移动一板后的真实相位变化。
7. **附加项**：基础和提高项稳定后再另立目标，不抢占主链验证时间。

## 7. 测量模型与误差预算

任务几何条件下：

```text
delta_ns = t_B_ns - t_A_ns
distance = c(T) * abs(delta_t)
delta_ns > 0：A先收到，声源在A侧
delta_ns < 0：B先收到，声源在B侧
```

这是双接收时间差，**不除以2**；声源不在基线延长线时，声程差一般不等于板间距。

目前项目选择ETH/PTP统一时间、共享整数温度与同一整数测距模型，细节见[硬件资源第5.5～5.9节](Hardware_Resources.md)。这些是设计约定，不是任务书强制使用的协议/公式，也未被现有空主循环实现。

以343 m/s作预算示例：10 μs对应3.43 mm，100 μs对应34.3 mm，2 mm约对应5.83 μs。因此同步和检测分别达到单项门槛，不能自动推出最终距离精度通过。若采用48 kHz采样，一样本约20.83 μs、对应7.15 mm；当前标称48kHz已实测，该例仍用于说明须评估亚采样定位和抖动，不能宣称精密样本时间已被当前采集结果验证。

分别记录固定偏差、随机标准差及最坏值，区分同步误差、采样时间映射、检测误差、温度/声速误差、双通道延迟和多径/声源差异。独立随机项才可按方差组合，固定偏差不能靠多次平均消除。

## 8. 应用模块与协议边界

按当前增量需要逐步创建，不预建整套空目录：

| 位置 | 职责 |
| --- | --- |
| `App/BSP/` | 逻辑资源映射及SDRAM/LCD/codec等板级服务，不替代CubeMX生成外设配置 |
| `App/Network/` | UDP传输、报文校验、版本/序号、重复/超时处理 |
| `App/Sync/` | 唯一时间服务、锁定状态及PTP到PPS观测路径 |
| `App/Audio/` | DMA缓冲所有权、样本序号、时间锚点与通道延迟 |
| `App/Detector/` | 检测、精定位、类型与质量 |
| `App/Measure/` | 事件配对、同一输入快照的距离/方向计算 |
| `App/Temperature/`、`App/Calibration/`、`App/UI/` | 温度共享、标定、结果与波形呈现 |
| `Tools/Monitor/`、`Analysis/`、`Logs/` | 开发观测、离线统计、原始日志；最终测量不依赖PC |

报文至少明确设备/会话身份、协议版本、消息类型、序号和有效负载长度。测量需关联事件类型、共同纪元、到达时间、温度/标定/算法版本和质量状态；明确字段宽度、单位及字节序，不直接发送依赖编译器填充的结构体。不要直接假定两板各自递增的本地事件号一定对应同一次声音。
