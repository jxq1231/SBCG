# 单板全事件对账与TOA离线回放执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. 使用下方复选框记录执行结果；本文件目前仅完成规划。

**Goal:** 对已有单板实验建立不漏账、可追溯、可重复计算的事件基准，分清声音候选、标准声身份、可用PCM窗口和到达时间，给下一次前沿算法选择提供可靠输入。

**Architecture:** 离线工具先保留全部原始记录并建立关联图，再从真实存在的PCM中提取完整窗口，调用冻结的真实C估算器。记录账本正确性、输入覆盖率和算法诊断三个独立结论；不改变板端行为，不把关联峰或名义微秒当作物理到达真值。

**Tech Stack:** Python标准库、已有NumPy分析函数、现有主机GCC测试模式、项目原TOA C接口；运行产物放在Logs，摘要放在Docs。

## 1. 当前目标与边界

当前里程碑：**M4声音检测——单板全事件对账与TOA离线回放**。只完成这一独立增量，随后停下复核结果。

它直接帮助最终两板测距的两项前提：A/B配对的必须是同一次、同类型发声；参与相减的时间必须来自完整且可追溯的样本。最终几何、d=c(T)|tB−tA|及提高项顺序见[目标路线](../Goal_Aligned_Roadmap_2026_10_26.md)。

- 本轮不改识别门限、前沿算法、PCM捕获/网口协议、时钟或屏幕。
- 不将子帧TOA接入PTP，不实现两板配对/距离核心；这些是后续独立目标。
- No CubeMX change required；没有新GPIO/TIM/DMA/NVIC/ETH/SAI/I2C/ADC/LTDC或缓存关系。
- 不需要第二板、示波器、网线、发声或烧录。现有文件不足的项目标为未知或缺失，不以补造数据完成验收。
- 保留用户未提交的`App/Detector/toa_estimator.c/.h`、`Tests/Detector/test_toa_estimator.c`和其他PPS/CubeMX改动。仅复制快照供主机回放，不替换工作区或混入提交。

- `source_snapshots/`、`windows/`、构建/测试日志：只用于本次可追溯复算，不提交生成物。

## 4. 顺序执行任务

### 任务1：冻结输入，先确认能分析到什么

- [ ] 记录`git status --short`、当前HEAD和用户已有改动；保持所有原文件不变。
- [ ] 九轮逐一枚举串口、summary、PCM和JSON，不以文件mtime推断固件版本；计算所有输入SHA256。
- [ ] 校验PCM为小端有符号16位、字节数为偶数、`bytes=frames×2`；文件名ID与JSON ID、串口CAPTURE元数据交叉核对。
- [ ] 记录JSON缺少的CH、采样率、UID、BOOT、镜像SHA。只有在同域日志/已冻结代码能提供旁证时填写，保存证据来源；否则UNKNOWN。
- [ ] 将两个具有相同回溯接口的算法快照分开：`c79bf25`的峰回溯版、执行时dirty工作区包络版；使用`git show <ref>:<path>`读取到Logs，不checkout或替换用户文件。源和头文件成对冻结，记录工作区版本实际哈希。A组旧日志另列历史观察，不把仅有正向接口的初版强行编入回溯适配器。
- [ ] 核对标准WAV与素材清单。`play_span`仅记录异步API调用时段，不推成声学起止或精确发声参考。

产出：输入清单及缺口表。作用：后续“改善”能够明确对应输入和算法，避免把不同固件日志混为一次实验。

### 任务2：建立不强行一一对应的事件账本

- [ ] 先写缺失、重复、跨trial、跨BOOT、同序号不同起点、坏JSON的失败测试，再实现解析/关联。
- [ ] 域采用`trial + boot_segment + session`。未捕获BOOT时使用该trial内UNKNOWN域；出现计数/帧倒退等冲突时断开关联，不能推断两段属于同一次启动。
- [ ] SEARCH、CAPTURE与PCM仅按同域ID精确关联，同时核对FIRST/FRAMES/HINT/RAW或BEST的对应字段；元数据冲突显式报错，不取最后一条覆盖。
- [ ] SOUND与SOUND_TIME使用同域`SESSION/SEQ/FIRST`。SOUND SEQ与CHIRP ID来自不同门控，禁止按序号相等直接关联。
- [ ] SOUND与CHIRP建立候选关联边：检查同域和声道证据，记录FIRST−HINT、捕获范围及帧邻近/重叠依据。存在关联证据但PCM缺左/右样本时仍保留边并标记缺窗；完整256点资格交给任务3独立判定。未证明声道一致时仍为待确认；多条相容边全部保留为AMBIGUOUS，禁止取最近者自动当真值。
- [ ] 以素材10个预期起点建立独立播放槽表，每槽允许0/1/多条候选。绝对对齐缺少独立参考时只记录可行关联及未知起始偏移，不默认首个候选就是slot0。
- [ ] 每条SOUND、SEARCH、CAPTURE和每个PCM/JSON孤立项都必须进入账本；没有播放槽的候选也保留。102/115是本次盘点基线，不是过滤目标。

最小可检查反例：C03的SOUND `SEQ26/FIRST5200064`与CHIRP `ID29/HINT5200000`相差64帧，不能因序号不同丢失，也不能只凭这一帧差认定唯一关联。B09第582行的背景候选与第598行后续响应必须同时可追溯，不能被合并成一个“通过”的slot9。

产出：全事件账本。作用：最终两板配错发声会直接产生错误距离和A/B方向，这一步先暴露误配来源。

### 任务3：只回放真实存在且资格明确的窗口

- [ ] 写完整256点、少1点、缺左沿、末尾截断、声道未知和多个PCM均覆盖等失败/对照测试。
- [ ] 对每个SOUND计算`anchor=max(FIRST−64,0)`，所需半开区间为`[anchor,anchor+256)`。
- [ ] 若PCM区间完整包含该窗且关联唯一，从小端PCM按绝对帧号提取512字节；禁止补零、裁窗或从不连续捕获拼接。
- [ ] 分别输出`offline_window_status`和`online_window_status`。前者只证明导出片段包含样本；后者需要当时半块/代码版本的证据。离线片段包含跨半块样本，不等于在线服务当时允许使用。
- [ ] 只有能证明对应版本的8192帧半块及CONFIRMED归属时，才用它判断在线资格；其余UNKNOWN。对旧缺左沿/未初始化尾窗记录不可信，不追认旧数字TOA。
- [ ] C适配器只接受恰好256个小端int16样本，拒绝少/多字节、非法输入和非有限结果；输出`valid`和相对窗首的`fraction_frames`。使用各冻结版本的默认配置，不改阈值。
- [ ] 按现有主机测试模式在O0/O2各编译一次，每个相同窗口重复两次。算法内输出应复现；编译或运行错误单独失败，不当作算法返回NA。
- [ ] 保留帧/子帧为主数据。名义微秒仅为`(anchor+fraction_frames)×1e6/48000`的诊断量，不当作PTP；不为凑日志一致人为添加固定偏置。

产出：逐事件、逐版本的真实C回放表。作用：算法比较可重复，边界失效、输入缺失与前沿选错能够分开定位。

### 任务4：用已知输入检查基准自身，不先改估算器

- [ ] 在同一验证入口加入有已知起点的PCM：斜坡、标准WAV、纯静音、单点尖峰、强回声。
- [ ] 固定合成参数：门控相位0..63；幅度倍数0.25/0.5/1；噪声0/32/128 PCM单位且随机种子固定；回声延迟24/96帧，增益0/0.5/1.5；相加后显式饱和到int16并记录削顶数量。
- [ ] 将已知信号起点、明确幅度跨阈位置、相关峰位置分别保存，不能互换参考。标准WAV首样本为淡入零值，不能将幅度跨阈偏置说成未知物理传播延迟。
- [ ] 验证框架对窗口不足、NA、重复或缺失都会保留记录；整窗平移后绝对坐标一致；0方差属于合法结果。
- [ ] 对冻结算法只输出各条件的有效覆盖率、偏置、最大/均方或标准差、选峰跳变；估算失败也是结果。没有达到期望的算法表现列为KNOWN_LIMITATION，不通过改测试或删样本修正。

产出：已知输入的对照诊断。作用：下一增量能选择一个有证据的前沿修正，不再靠反复播放或局部稳定槽猜测。

### 任务5：全量真实输入汇总，分开三种结论

- [ ] 九轮全部处理，输出原始计数→解析→关联→可回放→有效TOA的数量链；未知/无效/背景计数始终可查。
- [ ] 每轮列出标准识别MATCH、候选、缺失/多解、PCM有效窗及TOA NA；不以PEAK阈值删点后计算识别成功率。
- [ ] 只有播放槽完整唯一且对齐依据成立时才给全10次一致性指标；否则INSUFFICIENT，保留能算的局部诊断及未覆盖槽。缺少独立播放时刻参考时不发布物理TOA准确度PASS。
- [ ] 分开报告名义2s间隔残差、同槽跨轮归一化偏差及算法相对差，不混为一种“抖动”；共同偏置/比例项单列，不能逐槽拟合消掉差异。
- [ ] 真实PCM没有独立直达波真值，相关峰/人工可见起跳只能作参照；历史片段的负窗不自动等于60秒静默或击掌负样本。
- [ ] 按下方通过条件出具工具、覆盖率、声学精度三个结论；选择下一项最小修正及对应失败样本，暂不实施修正。

产出：可复查的诊断报告。作用：为两板测距分配真实误差预算，并决定下一步是补事件身份、补完整窗还是修前沿。

### 任务6：复核、提交、停在本增量

- [ ] 运行新测试、现有相关分析测试及原TOA/服务回归；检查O0/O2差异及重复输出。
- [ ] 独立只读复核是否丢事件、强行配对、跨版本混算或误报精度通过。
- [ ] 更新里程碑报告、当前状态和文档索引，只提交本轮新增工具/测试和相关文档。用户算法与硬件变更保持原样。

## 5. 测试与验收清单

工具测试采用临时目录生成最小JSONL/PCM，不依赖本机完整Logs才能执行。先写断言并观察缺失实现/错误关联的失败，再实现最小代码。

| 测试输入 | 必须观察到的结果 |
| --- | --- |
| 两个trial均SESSION1/ID1 | 两个独立事件，不能合并 |
| 一trial内出现BOOT或帧/序号倒退 | 分域或标冲突，不跨域配对 |
| SOUND SEQ26与CHIRP ID29、相容帧范围 | 保留关联候选，不能以SEQ不等丢弃 |
| 一SOUND与两个PCM相容 | AMBIGUOUS，两个候选边都存在 |
| 单独PCM或单独JSON、坏JSON、字段冲突 | 孤立/错误项均列出并保留来源 |
| 窗长256与255、缺左沿 | 前者可调用C；后两者NA且不补零 |
| PCM够窗但历史在线半块不允许 | 离线可观察/在线不可用分列 |
| 两个事件同slot、缺一个slot、只有一轮 | 不能产生全十次重复性PASS |
| 十个完整唯一合成槽且误差全0 | 框架一致性可PASS，不因方差0误判失败 |
| 无独立发声参考的真实PCM | PHYSICAL_TOA_ACCURACY=NOT_VERIFIED |
| 同输入、同源哈希、同配置重复运行 | 去除运行时间/路径后结果相同 |
| 额外背景事件 | 仍在记录/汇总中，不随归槽失败消失 |

## 6. 何时需要用户配合，下一阶段怎样衔接
