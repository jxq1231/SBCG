# M3.2.1 音频帧序号实现计划

状态：用户已批准实施及本版本烧录；软件、正常窗口实机及独立复核通过，保留轮询抖动边界。详见 ../Milestones/M3_2_1_Audio_Frame_Index.md。

目标：在当前单板连续采集中，为每个可消费的音频块提供会话、首帧、帧数、已知缺口和编号可信状态。不做 PTP 映射、检测、双板同步或测距。

## 接口与边界

- 一帧是同一采样时刻的左右声道两个 int16_t；半缓冲区为 8192 帧。
- SESSION 为本次启动内非零 uint32_t 采集尝试编号，真正启动 DMA 前分配；失败尝试也消耗编号。复位后重新从 1 开始，必须结合 BOOT 分段，不能充当跨复位唯一身份。拒绝回绕。
- OBS_FRAMES 为 uint64_t 已观察边界数乘以 8192；每个回调增加，不随前台丢块压缩。FIRST 为当前消费块的零基首帧，COUNT 为 8192。
- GAP 为相对上一成功 End 的已知未交付帧数；会话起点的上一末帧视为 0。CONTIG 只说明当前块与此前成功交付范围相邻，不能跨 SESSION 使用。
- 回调顺序异常、HAL/DMA 错误、观察间隔超过 250 ms 或 uint64_t 计数溢出，锁存编号错误；仅新采集会话恢复。250 ms 是根据当前约 170.7 ms 半块周期设置的保守异常观察阈值，不是精密计时。
- 计数只对应观察到的 DMA 边界。IRQ 标志会合并，HAL tick 也不提供长时间关中断时的独立时间证明；INDEX_VALID 表示没有被软件检查发现歧义，不能证明不存在未观测的完整循环。前台遗漏的、已观察到的块可量化缺口；不可确定的硬件遗漏不虚构数量。
- 保留现有 Begin/End 缓冲区所有权检查。跨会话旧 token 即使 generation/half 相同也必须拒绝。编号失效不妨碍原幅值诊断，但不能输出有效位置。
- 新增每秒 $AUDIO_POS，与原 $AUDIO 共用 SEQ；旧 $AUDIO 字段保持兼容，FRAMES 改用相同 uint64_t 观察计数。VALID=0 时位置清零，不发布旧位置。

## 资源及调用链

No CubeMX change required。沿用 SAI2-B RX、DMA2 Stream7 Channel0、32768 个 halfword 的 circular 缓冲区；半满/满各交接 8192 帧。SRAM1 0x20010000 的 64 KiB、32 字节对齐缓冲区不变。I/D Cache 关闭，不增加缓存维护。

DMA2_Stream7_IRQHandler → HAL DMA → SAI 半满/满回调 → 有界编号/交接；SAI2 错误回调锁存无效。前台 App_Process → AudioCapture_Process → Begin → 统计 → End → 每秒日志。IRQ 内不做串口、PTP、I2C、统计或分配。

## 预定验收

主机覆盖计数越过 uint32_t 帧边界、uint64_t 溢出拒绝、HAL tick 回绕、前台跳过两个块仍保留 16384 帧缺口、异常后不恢复、重新采集新会话及旧 token 失效。正常实机窗口至少 60 对逐秒 AUDIO/AUDIO_POS：SESSION 不变，OBS_FRAMES 与 H/F 对应且增长，FIRST 对齐 8192、COUNT=8192、GAP=0、INDEX_VALID/CONTIG/VALID=1、FAULTS=0；DROP/ERR/HAL/DMA=0，并复验温度、心跳、原 UDP 请求及时间戳观测。每秒只观察最新消费块，不宣称日志逐块导出所有 PCM。
