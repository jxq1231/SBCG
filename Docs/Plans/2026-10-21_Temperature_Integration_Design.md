## 2. 用户当前需要完成的CubeMX步骤

1. 打开当前工程`SBCG.ioc`，进入Pinout & Configuration。
2. 在芯片图搜索/定位PG7，将其设为GPIO_Output。
3. 在System Core → GPIO选择PG7，设置以下参数。

| 项目 | 设置 |
| --- | --- |
| User Label | DHT11_DATA |
| GPIO output level | High |
| GPIO mode | Output Open Drain |
| GPIO Pull-up/Pull-down | No pull-up and no pull-down |
| Maximum output speed | Low |

4. 保存，执行Generate Code；保留当前GCC/CMake、SYS、200MHz时钟及已有ETH/LwIP设置。
5. 生成后通知“PG7已生成”，由代码侧重新检查差异，再接入应用模块。此时不需要提前接线或烧录。

这是新增一个未分配引脚，不替换现有资源。当前GPIOG时钟已由生成代码开启；PG11/13/14继续用于ETH，PG7不与其重叠，也不占PA15/PPS、PH7/PH8的I2C3或板载显示/音频连线。预期主要变化为`SBCG.ioc`、`Core/Inc/main.h`和`Core/Src/main.c`；生成器元数据若变化也逐项检查。不手改.ioc或生成初始化，不照搬队友的TIM2/LTDC/FMC配置。

生成后的检查目标是存在DHT11_DATA两个宏、PG7先写High且初始化为OD/NOPULL/LOW；已验收的SYS/RCC/ETH/LwIP、DMA、NVIC及链接布局保持原配置。未通过这个检查前不写功能代码。

## 3. 传感器位置和接线

DHT11是板外模块，不是MCU内部温度计。按本工程已核对的连接器映射：

| 模块信号 | STM32F746G-DISCO位置 |
| --- | --- |
| DATA / S | PG7，Arduino D4，CN4第5针 |
| VCC / + | 3V3，CN6第4针 |
| GND / - | CN6第6或第7针 |

三针模块按实际丝印确认，不根据插针左右顺序猜电源。模块需支持3.3V供电，DATA上拉到3.3V；核对模块已有上拉，不能用内部弱上拉替代。裸器件4脚与三针小板不同，裸件的NC不接。短线连接；传感器放在板外通风、靠近实际声传播环境的位置，避开MCU、背光和稳压器热源。[现有板级依据](../Hardware_Resources.md#46-dht11温湿度接口单只接a板pg7--arduino-d4b板接收udp温度)

当前UID `001A002D:30365105:36363631`仅作为本轮采样测试板；不据此认定最终A/B角色。其他UID默认不主动采样，并显式说明未启用。本轮不检查第二板。

## 4. 分层和实时边界

- `App/BSP/bsp_dht11.c/.h`：逻辑引脚写低/释放/读电平，DWT周期计时与有界波形采集；只使用CubeMX生成的标签，不再调用HAL_GPIO_Init更改模式。
- `App/Temperature/dht11_frame.c/.h`：纯40位帧解码和校验，不依赖HAL。
- `App/Temperature/sound_speed.c/.h`：纯整数温度到声速计算。
- `App/Temperature/temperature_service.c/.h`及`temperature_config.h`：采样状态机、唯一测试UID、周期/时效常量和串口快照；协调BSP、解码与声速函数。
- `App/app_main.c`：只增加Init/Process和新版本标识；放在既有主循环业务之后。
- 用户拥有的根`CMakeLists.txt`注册源码，生成CMake不改。

上电至少等待1秒。采用5秒采样间隔，所有重试也遵守该间隔；首次及长时间停读后先预读，下次5秒周期读数才用于新快照。起始低电平目标20ms，用主循环状态机等待；若实际拉低时长超过手册30ms上限，释放并报错，不继续解码。

响应和40位读取使用DWT做脉宽计时，单次捕获整体限制6ms，各边沿均有超时与位宽检查。DWT换算依据实际SystemCoreClock，周期差按无符号减法处理回绕；DWT只服务协议时序，不成为测距时间源。不全局关中断、不改SysTick、不占TIM2，不在ISR或网络包装中采样；不为20ms起始低电平调用HAL_Delay。

6ms是轮询协议期限，不是任意中断抢占下的硬性墙钟上限；恢复执行后检查并拒绝过期帧。必须在网络/PTP并行运行时实际记录主循环捕获延迟及失败率；不能仅凭低负载温度成功就声明实时链路无影响。如果联测不能满足原业务或可靠性边界，停止本增量并重新评估捕获方式，不偷偷增加EXTI、定时器或DMA。

IRQ：无新增关系。DMA：无新增关系，CPU私有帧与快照不交给DMA。I/D Cache和MPU不变，不增加缓存维护。ETH/PTP配置、原网络协议与原估算器保持不变。

## 5. 数据、声速和状态

按V1.3手册，5字节为RH整数、RH小数、温度整数、温度小数/符号、校验；前4字节之和低8位必须等于第5字节。RH小数字节要求0；温度小数字节bit7为负号，低7位是十分之一度且必须0～9。校验通过再检查RH 5～95%、温度-20～60℃。旧模块常见的小数0正温帧可由同一格式解码，其他器件格式不自动猜测。

统一变量为`int32_t temperature_milli_c`、`uint32_t relative_humidity_milli_pct`和`uint32_t sound_speed_mm_s`。沿用硬件文档math_version=1：

```text
sound_speed_mm_s = 331300 + round_signed(606 * temperature_milli_c / 1000)
```

乘法用int64_t；正负恰半均远离零。模型输入先检查-20000～60000毫摄氏度，错误不覆盖输出。这是干空气线性近似，没有加入湿度/气压修正；小数表示能力不等于传感器精度。

| 输入 | 期望 |
| --- | --- |
| 53,0,24,4,81 | 24400毫摄氏度、53000毫%RH、346086mm/s |
| 53,0,10,129,192 | -10100毫摄氏度、325179mm/s |
| 20.000℃ | 343420mm/s |
| 25.000℃ | 346450mm/s |
| -10.000℃ | 325240mm/s |
| 0.000℃有效校验帧 | 有效0℃；不能当作失败 |

首个有效正式样本前为UNREADY，不伪造25℃/0℃，不输出有效声速。读数成功后增加温度版本并保存采样tick；超时、脉宽、校验或范围失败不覆盖最后成功值，标记HOLD_LAST并保留年龄，连续恢复后再更新版本。15秒以上未成功更新显式标记STALE。每秒最多一条TEMP状态和一条独立TEMP_STATS统计，不在起始低电平及捕获期间打印本模块日志。计数区分尝试、成功、预读、初始化/总线/起始窗口/超时/脉宽/时钟/校验/范围及本地格式失败；实际串口发送失败由App既有HEARTBEAT/TX_ERRORS统计。R0允许旧业务串口在起始低电平期间阻塞；R1由App将这段时间的全部应用日志暂存到16项固定FIFO，DATA释放后每轮至多发送一条，满队列计入TX_ERRORS。温度模块提供只读busy查询，网络/PTP处理顺序不变，不改变时序阈值或采集硬件。其他阻塞仍可能导致超30ms并安全释放，R1须联合实测。

日志使用整数单位，包含STATE、VERSION、T_MILLI_C、RH_MILLI_PCT、C_MM_S、AGE_MS、FRESH及计数；UNREADY/禁用时不附带虚假数值。故障后保留的声速是历史快照，不宣称新测量有效。
