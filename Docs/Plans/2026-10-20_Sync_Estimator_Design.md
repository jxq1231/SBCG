# M2.2.1 四时间戳偏差与路径时延估算器设计

日期：2026-10-20。基线ccbb001，工作区干净。状态：设计待用户确认，未修改固件、未实现估算器、未烧录。M2.1.3单板RX/TX事件关联已验收，仍为LOCAL/SYNC=0；本轮继续不检查第二块板。

## 独立目标与选择

以不依赖HAL或网络的纯C函数，验证一组四时间戳能否正确计算有符号时钟偏差和平均单程路径时延，并拒绝越界、倒序、超窗及负路径时延输入。目标是数学内核可复用且可测试，不是完成同步闭环。

| 路径 | 交付与依赖 | 本次安排 |
| --- | --- | --- |
| 先验证四时间戳估算器 | 电脑原生测试即可核对正负号、半纳秒表示和整数范围；不需要第二板或硬件改动 | 推荐作为M2.2.1 |
| 接入同步报文与样本配对 | 需定义双端身份/会话、序号、超时、TX后续通知及完整四时间戳归属；再逐步接入校时 | 留给后续独立设计 |
| 先验证PTP整秒输出 | 需CubeMX配置TIM2/PA15及PTP内部触发，生成后进行波形测量；对应M2.3 | 按路线另立硬件增量 |

现有电脑工具只记录软件请求/应答时刻，本板串口只提供本板RX/TX硬件时间。它们不能作为双板硬件四时间戳或±10 μs同步精度证据。本次用明确标注的合成样本验证数学，不将日志中的131～143 μs本板处理间隔当作时钟偏差。

## 数学定义与单位

A、B仅为数学中的两个时间域，尚不指定当前板的A/B角色。四个输入为同一轮交换、各自时钟连续运行时的整数纳秒：

| 字段 | 含义 | 类型 |
| --- | --- | --- |
| t1_a_tx_ns | A发送时刻，属于A时钟 | uint64_t |
| t2_b_rx_ns | B接收时刻，属于B时钟 | uint64_t |
| t3_b_tx_ns | B发送返回消息时刻，属于B时钟 | uint64_t |
| t4_a_rx_ns | A收到返回消息时刻，属于A时钟 | uint64_t |

定义a=t2−t1、b=t4−t3，二者必须以有符号差值计算。偏差正值表示B领先A，负值表示B落后A：

```text
offset_B_minus_A = (a - b) / 2
mean_path_delay  = (a + b) / 2
round_trip_path = (t4 - t1) - (t3 - t2) = a + b
```

四时间戳偏差及扣除对端驻留时间的往返时延关系参照[RFC 5905第8节](https://www.rfc-editor.org/rfc/rfc5905.html#section-8)。这里仅使用共同的双向授时数学模型，不引入NTP报文或宣称实现完整IEEE1588协议。平均单程时延取往返路径时延的一半；在本设计的双向对称、短交换期间频率差可忽略的假设下，将其用于偏差估计。路径不对称会产生估计偏差，单组四时间戳不能辨别该不对称。

输出保留精确整数分子：int64_t offset_x2_ns=a−b，int64_t mean_path_delay_x2_ns=a+b。字段值是对应纳秒量的两倍，例如offset_x2_ns=-1表示-0.5 ns，不执行除法或舍入，不使用浮点。这是数值表示能力，不代表当前5 ns硬件时间戳具有0.5 ns测量精度。后续界面需要整数纳秒时再独立规定舍入，禁止现在静默截断。

## 范围、接口及失败规则

接口拟为SyncEstimator_Calculate(const SyncExchange *exchange, uint64_t max_exchange_ns, SyncEstimate *result)，返回SyncEstimatorStatus。SyncExchange仅含上述四个输入字段，SyncEstimate仅含两个输出字段；类型定义全部放App/Sync/sync_estimator.h，不依赖BSP头文件。函数无全局状态、动态分配、日志、硬件访问或校时副作用。

每个输入上限为4294967295999999999 ns，即当前32位秒及十进制纳秒能表达的最大值。先检查四个无符号输入范围，再转int64_t、再求差；不得先做无符号减法后强转。最大二阶和/差为8589934591999999998，小于INT64_MAX=9223372036854775807，因此通过输入检查后整数计算范围可证明安全。

检查顺序及状态固定如下：

1. exchange/result为空：SYNC_ESTIMATOR_BAD_ARGUMENT。
2. max_exchange_ns为0、超过上述输入上限，或任一时间戳越界：SYNC_ESTIMATOR_OUT_OF_RANGE。
3. A域t4<t1或B域t3<t2：SYNC_ESTIMATOR_BAD_ORDER。仅比较同一时钟域内的先后，不能要求跨域t2≥t1；跨域差为负可能是合法偏差。
4. A域t4−t1或B域t3−t2超过max_exchange_ns：SYNC_ESTIMATOR_WINDOW_EXCEEDED。窗口上限由调用者显式传入；测试使用1000000000 ns，不设实机默认超时。
5. a+b<0：SYNC_ESTIMATOR_NEGATIVE_DELAY。返回错误，不能取绝对值或夹为0掩盖问题；a+b=0允许。
6. 其余输入：SYNC_ESTIMATOR_OK，一次性写出两个结果。任何失败都保持非空result的原值不变。

调用者负责提供有效、配对、属于同一会话/纪元且未在交换中被校时的四时间戳。本函数无法从四个数字验证UID、消息来源、硬件捕获有效性或发现所有跨轮混配，不能以检查通过宣称这些条件成立。32位秒回绕、重启及时间跳变由后续会话层处理，本增量不自动展开跨纪元数据。

## 确定性验收样本

以下数值均为纳秒，期望结果均为两倍纳秒表示。既测试普通有效值，也测试时钟差大于单程时延、导致某个跨域差为负的合法输入。

| 场景 | t1 / t2 / t3 / t4 | offset_x2_ns | mean_path_delay_x2_ns |
| --- | --- | ---: | ---: |
| B领先50 μs，双向各100 μs | 1000000000 / 1000150000 / 1000350000 / 1000400000 | 100000 | 200000 |
| B落后50 μs，双向各100 μs | 1000000000 / 1000050000 / 1000250000 / 1000400000 | -100000 | 200000 |
| 零偏差，双向各100 μs | 1000000000 / 1000100000 / 1000300000 / 1000400000 | 0 | 200000 |
| B落后500 μs，跨域差为负 | 1000000000 / 999600000 / 999800000 / 1000400000 | -1000000 | 200000 |
| 半纳秒分子保留 | 1000 / 1001 / 1002 / 1002 | 1 | 1 |
| 双向150/50 μs，B领先50 μs | 1000000000 / 1000200000 / 1000400000 / 1000400000 | 200000 | 200000 |

最后一行输出偏差100 μs，体现路径不对称带来的50 μs误差，不能错误地要求它返回真实50 μs或伪称能够识别不对称。
