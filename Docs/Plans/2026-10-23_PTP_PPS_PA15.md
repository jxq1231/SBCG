## 两板相同的输出与接线

| 用途 | 位置 |
| --- | --- |
| A/B PPS_OUT | PA15 / TIM2_CH1 / AF1，绿板Arduino D9 / CN7第2针 |
| A示波器 | CH1探头接A的D9，地夹接A的GND |
| B示波器 | CH2探头接B的D9，地夹接B的GND |
| 绿板GND例 | CN6第6或第7针，按板上GND丝印核对 |

蓝色扩展板若转接D9，使用D9组的信号9端及GND；同组供电脚不作为PPS信号。A/B输出线分别接示波器，不能将两个输出端直接相连。输出目标0～3.3V、高阻/10×探头，两板继续通过交换机连接。

生成前.ioc没有PA15/TIM2配置，原SWD+SWO不会占用PA15；USART1、ETH RMII、SAI2、DHT11 PG7/D4无引脚重叠。PB5有板载USB PHY连线，本增量沿用已规划PA15。

## CubeMX操作（由用户执行，No hand-edit .ioc）

打开SBCG.ioc，进入Pinout & Configuration → Timers → TIM2：

| 页面/参数 | 设置 |
| --- | --- |
| Clock Source | Internal Clock |
| Slave Mode | Reset Mode |
| Trigger Source | ITR1 |
| Channel1 | PWM Generation CH1 |
| PA15 | TIM2_CH1；确认没有落到PA0等其它候选脚 |
| PA15 User Label | PPS_OUT |
| Prescaler / PSC | 99 |
| Counter Mode | Up |
| Counter Period / ARR | 4294967295，即0xFFFFFFFF |
| Clock Division | DIV1 |
| Auto-reload preload | Disable |
| CH1 Mode | PWM mode 1 |
| CH1 Pulse / CCR1 | 100 |
| CH1 Output Compare Polarity | High |
| CH1 Fast Mode | Disable |
| ITR1 remap capabilities for TIM2 | TIM2 ITR1 input is connected to PTP trigger output |
| PA15 GPIO | Alternate Function Push Pull，Pull-down；速度Low可保留，必要时经示波器确认再提高 |
| TIM2 NVIC / DMA | 不新增中断，不新增DMA |

APB1当前50MHz、定时器时钟100MHz，经PSC99得到1MHz、CCR100对应100us。ARR最大值用于使每秒上升沿由PTP触发产生；应用启动时须设置安全CNT并确认低电平，不以计满一秒产生PPS。

本机CubeMX6.18.1的`db/mcu/IP/TIM1_8F7-gptimer2_v3_x_Cube_Modes.xml`明确提供参数`TIM2_ITR1_REMAP`，可选值`TIM_TIM2_ETH_PTP`，上述英文即实际选项文字。若界面找不到该项，先保存界面信息核对，不手改.ioc或生成初始化，也不改选其它触发源。

保存并Generate Code。预计Core/Src/main.c（htim2/MX_TIM2_Init）、Core/Src/stm32f7xx_hal_msp.c、Core/Inc/main.h、Core/Inc/stm32f7xx_hal_conf.h、HAL TIM驱动、CubeMX CMake登记与.ioc发生相关变化；分文件模式可能改为tim.c/.h。保留原ETH、UART、SAI、温度、用户钩子及内存布局。

## 应用层实现范围（生成后实施）

- App/BSP/bsp_pps.c/.h：统一映射htim2/CH1与PPS_OUT，校验生成配置、停止/安全启动输出及PTP触发状态，不重写生成配置。
- App/Sync/pps_service.c/.h：管理输出资格与故障状态；BSP逐秒预装PTP目标时间比较触发。TIM2 ITR1连接的是PTP目标时间比较事件，不是PTPPPSCR的独立周期PPS；以RM0385和实物验证为准，不把主循环翻转GPIO作为验收边沿。
- App/Sync/time_sync.c：Observe后、Commit前将瞬时锁证据交给PPS服务，并在相位写入、拒绝、故障或B对端重置时同步撤资格；不新增通用观察框架。A对端重置不改变其本地参考时间，参考PPS保留。
- App/app_main.c、用户CMakeLists.txt：生命周期和DHT门控；main用户区只有必要接入，硬件初始化由生成代码负责。
- Tests/PpsBsp、PpsService、PpsIntegration及App/PTP关联回归：初始输出低、整秒触发、跳时/失联/故障、无伪脉冲、重新资格与原业务。

A在本地PTP健康时输出参考PPS；B首次内部资格满足后输出，失联、无效时钟、相位覆盖或对端代际变化时撤销资格。现有B每约8秒调频会清除连续锁证据，PPS资格不能简单等同瞬时INTERNAL_LOCK，否则难以采集连续10次脉冲；应单独定义短暂频率重估期的有界资格保持，并在实现前冻结具体时效门槛。频率变化不应被误当作相位跳变。上述机制已在应用中实现，软件证据及未测边界见[本轮交付](../Milestones/M2_3_3_PTP_PPS.md)。

## 补生成后的实施任务与冻结门槛

- [x] 核对GPIO_PULLDOWN，保存生成快照SHA，恢复再生成误删的原组件许可。
- [x] BSP：只提前预装下一次整秒比较，100ms提前裕量；单次目标必须在调用者资格剩余时间减100ms范围内。MACSR.TSTS轮询并读PTPTSSR清状态，不使用已知与RM位号冲突的CMSIS TSTTR宏。安全关闭CC1E/CEN，UG装载后CNT100并有界预运行到101再启通道，防止软件首脉冲；不新增IRQ/DMA。
- [x] 服务：B首次合格内部锁后取得资格；接受样本captured_ms年龄<2000ms。纯频率更新绝对差<=1125ppb才可连续输出，成功后RATE_REQUALIFY期限<4000ms；期间第二次变频或坏样本撤销，不能不断续期。初次锁的观察必须在Observe后、Commit前交接。A本地PTP健康才排参考脉冲；SYNC仍0。
- [x] 时钟初始化/相位覆盖/时钟失效前同步停PPS，Stop失败不得写相位。频率成功不无条件停PPS。外部epoch/rate/peer变化、拒绝和FAULT同步撤资格。
- [x] App安全轮询不因DHT低态整个跳过；主动排程及日志可以延后。保持现有伺服、音频DMA和网络行为，新增用户文件通过顶层CMake登记。
- [x] 原生红绿负例、原模块与工具回归、Debug/Release、ETH/音频布局、生成快照哈希保持核对。应用接入后未再次实际Generate Code；本轮独立复核发现跨整秒读取竞态，已补四个读取点注入红绿测试并修复为32次/2ms有界一致性复核，复核确认无新增重要问题。
